Producer Manual

This comprehensive guide covers everything a Producer needs to know to manage a live event using the Stream Production Manager.

1. Dashboard & Productions

When you load the app, you arrive at the Dashboard. Here, you manage all your "Productions" (e.g., individual tournament days, separate events).

  • Create New: Click the "Create Production" button to start a blank canvas.
  • Import: Drag and drop a previously exported .json file to restore a full production configuration, including settings and timeline.
  • Export: Click the Export icon on any existing production to save a backup to your local computer.

2. The Producer Layout

Clicking into a Production takes you to the Producer View. This screen is divided into three functional columns:

Left Column: Controls & State

This panel gives you overarching control over the broadcast state and features utility tools.

  • Production Name: Editable directly at the top.
  • Master Status: Displays whether the show is IDLE, LIVE, or PAUSED.
  • Playback Controls: The Start/Resume/Pause buttons control the Master Status. Clicking Start pushes the first timeline item to LIVE.
  • Settings: Opens the Settings modal (configure Caster names, OBS Scenes, etc.).
  • Caster Message: A dedicated panel to push urgent text alerts directly to all Caster screens. Type a message, click Send, and click Clear to dismiss it.

Center Column: The Timeline

This is your active rundown. It represents the chronological flow of the show.

  • Active Item: The currently live segment is highlighted in vibrant red with a pulsing glow.
  • Reordering: Grab the ⠿ handle on the left of any item to drag and drop it anywhere in the timeline.
  • Inserting: Click the + Add divider between any two items to instantly insert a new item at that exact position.

Right Column: Standby & Active Detail

This split panel handles upcoming, unassigned items and the hyper-focus view of what's live.

  • Standby List (Top): A staging area for items that aren't yet scheduled on the timeline. You can draft items here and drag them into the Timeline later.
  • Active Item Detail (Bottom): A magnified view of the currently LIVE segment. It displays full notes, configured metadata (like which Casters are on desk), and OBS scenes. This is where you actually check off tasks in a Task List.

3. Events vs. Task Lists

When you add an item, you choose between two primary object types:

Event

A standard segment of the show (e.g., Gameplay, Interview, BRB). Events have specific "Event Types" which dictate their color coding and the custom fields you can fill out.

  • Example: A "Gameplay" event will ask for Table, Round, and assigned Casters. An "Interview" event will ask for the Player Name and Interviewer.
  • Each event type is automatically color-coded with a distinct, CSS-driven palette so you can scan the rundown visually.

Task List

A checklist for the production crew, colored in Amber. These do not push metadata to the casters; instead, they give the Producer a checklist to run through.

Important Task List Behavior

When a Task List is the active item, the ✓ Mark Complete button is disabled until all checkboxes in the Active Detail panel are ticked. This ensures critical pre-flight sequences (like unmuting mics or firing ads) are not skipped.

4. Navigating the Show

As the Producer, you drive the state of the broadcast:

  • Mark Complete: Clicking the ✓ button on the active item immediately pushes it to the "Completed" state (it grays out) and automatically activates the next item in the timeline.
  • Jump To Item: Clicking the ▶ button on any pending item immediately makes that item LIVE, skipping anything in between. Skipped items get crossed out.

5. Settings & Settings Modal

Click the ⚙ Settings button in the left panel to open the configuration.

  • Info Tab: Change the Production Name or estimated run length.
  • Data Lists Tab: Define the list of available Casters and OBS Scene names. These populate the dropdown menus when creating items.
  • About Tab: Software licensing info and links to this documentation.
